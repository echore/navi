<h2>这个工作流做了什么</h2>
<p>用一句话概括：<strong>把一个项目里积累的零散经验，通过结构化的提问和迭代，最终转化成可以跨项目复用的系统。</strong></p>
<hr>
<h2>完整流程，分六个阶段</h2>
<h3>阶段一：原材料准备</h3>
<p>起点不是从零开始，而是已有一份文档——把之前多个 Session 的 AI 总结，汇总成一篇笔记。</p>
<p>这份笔记是整个工作流的原材料。它记录的是&quot;发生了什么&quot;，但还没有经过真正的消化。</p>
<p><strong>关键动作</strong>：在开始新 Session 之前，先让 AI 把历史内容整理成结构化的笔记，而不是每次从头解释背景。</p>
<hr>
<h3>阶段二：结构化提问</h3>
<p>拿着这份笔记，一个问题一个问题地问。不是&quot;帮我解释这份文档&quot;，而是针对其中每一个具体知识点追问：</p>
<ul>
<li><p>这是什么意思？</p>
</li>
<li><p>为什么会这样？</p>
</li>
<li><p>大家一般怎么做？</p>
</li>
<li><p>这说的对不对？</p>
</li>
</ul>
<p>每个问题都有 follow-up，直到真正理解为止。</p>
<p><strong>关键动作</strong>：问&quot;为什么&quot;，不只问&quot;是什么&quot;。追问到原因，才算真正消化。</p>
<hr>
<h3>阶段三：复盘与提炼</h3>
<p>每个项目或阶段结束后，不要直接开始下一件事，先停下来问：<strong>这次哪里做得好、哪里做得不好、为什么？</strong></p>
<p>复盘不是自我批评，是提取可以复用的模式。</p>
<p><strong>关键动作</strong>：追问到根因，不停在现象。&quot;测试没做好&quot;是现象，&quot;没有强制要求汇报测试结果&quot;才是原因。只有找到原因，才能改变下一次。</p>
<p>详细的复盘问题清单和执行标准，见 [[项目复盘标准：怎么复盘才能真正积累]]。</p>
<hr>
<h3>阶段四：从复盘到 SOP</h3>
<p>复盘出来的经验，不是所有都值得进 SOP。进 SOP 的标准是：</p>
<ul>
<li><p><strong>重复性</strong>：这个问题会在下个项目里再出现吗？</p>
</li>
<li><p><strong>可预防性</strong>：能靠一条规则提前避免吗？</p>
</li>
<li><p><strong>可验证性</strong>：这条规则有没有执行，能被检验吗？</p>
</li>
</ul>
<p>三条都满足才进 SOP。写进去的格式：说清楚做什么、什么时候做、怎么验证。</p>
<p>SOP 不是一次写完的，是每次发现问题就迭代的。第一版永远不完美，重要的是持续更新。</p>
<p><strong>关键动作</strong>：SOP 从真实踩坑里提炼，不是凭空想出来的。没有踩过的坑，写不出有生命力的规则。</p>
<hr>
<h3>阶段五：让系统自我延续</h3>
<p>SOP 写好了，还需要三个环节让它真正运转：</p>
<p><strong>入口</strong>：新项目开始时，有固定的触发动作启动系统。<br>→ 读 SOP，建项目专属规则文件（如 CLAUDE.md），建项目笔记和阶段清单。</p>
<p><strong>容器</strong>：运行中，规则和进度有固定的存放位置，AI 每次都能读到。<br>→ 规则存在项目配置文件里，进度和交接存在笔记里，两处分工明确。</p>
<p><strong>出口</strong>：项目结束时，有固定动作把新经验写回系统。<br>→ 做复盘，符合标准的经验更新 SOP，Session 结束写交接。</p>
<p><strong>关键动作</strong>：三个环节缺任何一个，系统就会断。入口保证启动，容器保证运行，出口保证积累。</p>
<hr>
<h3>阶段六：双向链接，形成知识网络</h3>
<p>所有产出的笔记不是孤立的，而是通过 Obsidian 双向链接连接起来：</p>
<ul>
<li><p>SOP 链接到参考来源（五篇文章）</p>
</li>
<li><p>五篇文章链接回 SOP</p>
</li>
<li><p>学习笔记链接到 SOP</p>
</li>
<li><p>这一切形成一个可以互相索引的知识网络</p>
</li>
</ul>
<p><strong>关键动作</strong>：笔记不是写完就放着，而是要和已有的知识连接起来，才能在未来被真正用到。</p>
<hr>
<h2>这个工作流的本质</h2>
<p>不是&quot;学了什么&quot;，而是<strong>建立了一套让知识自我积累的系统</strong>。</p>
<p>每次 Session 的产出不只是当次的答案，而是：</p>
<ul>
<li><p>更新的笔记（原材料变好）</p>
</li>
<li><p>更完善的 SOP（系统变强）</p>
</li>
<li><p>更多的双向链接（网络变密）</p>
</li>
</ul>
<p>下一次 Session 站在更高的起点上，而不是每次从零开始。</p>
<p>这就是复利。</p>
<hr>
<h2>可以直接复用的流程模板</h2>
<pre><code class="language-plain">1. 准备原材料
   → 让 AI 把历史 Session 整理成结构化笔记

2. 结构化提问
   → 针对每个知识点问&quot;为什么&quot;，追问到原因

3. 做复盘
   → 做完一件事，问&quot;下次怎么做得更好&quot;

4. 提炼成 SOP
   → 先列自己知道的，再搜行业标准，再迭代

5. 让系统延续
   → 建 CLAUDE.md，把规则固定下来

6. 连接知识网络
   → 双向链接，让新笔记和已有知识对话
</code></pre>
